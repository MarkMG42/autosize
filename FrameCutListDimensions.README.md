# Размеры всех тел выбранной детали рамы

`FrameCutListDimensions.bas` — отдельный самостоятельный VBA-модуль для SolidWorks
2025. Он обрабатывает **каждое тело списка вырезов одной выбранной детали рамы**
на текущем чертёжном виде сборки. Другие компоненты, даже если у них есть свой
список вырезов, в обработку не попадают. Вид отдельной детали также поддерживается.

Рабочая проба `FrameCutListDimensionTrial` 1.3 сохранена отдельно. В пользовательском
запуске она создала истинный размер 710 мм и достигла заданной позиции в изометрии.
Массовый режим добавляет обход тел, автоматический выбор рёбер, исключение
подтверждённых существующих размеров и отдельную калибровку для каждой аннотации.

## Подтверждённый массовый запуск и трубы

Пользовательский запуск v1.0 подтвердил 11 корректных размеров швеллеров/уголков
из очереди 19 тел. Восемь профильных труб пропущены: исходная геометрия имеет
по 16 продольных рёбер полной длины, но они не попали в подходящие видимые рёбра
чертежа. Для проверки кромки возле скругления добавлен отдельный
[FrameTubeDimensionTrial](FrameTubeDimensionTrial.README.md). Этот исходник
массовой версии сохранён без изменения работающей логики швеллеров и уголков.

## Запуск

1. Импортируйте **FrameCutListDimensions.bas** в VBA-проект SolidWorks.
   Это самостоятельный модуль; старые Trial/Probe не нужны как зависимости.
   Нужны стандартные ссылки SldWorks и SwConst.
2. Выполните Debug → Compile.
3. На копии чертежа выберите **одно ребро самой многотельной детали рамы**.
   Оно задаёт нужный экземпляр и чертёжный вид; не требуется выбирать все тела.
   Дополнительное выделение рамки вида допускается, несколько рёбер — нет.
4. Запустите **`FrameCutListDimensions.main`**.
5. Проверьте отчёт: сколько тел уже имели подтверждённый размер, сколько размеров
   создано, какие тела пропущены/не обработаны и почему. Файл полного Unicode-журнала
   сохраняется в TEMP; путь показывается по завершении.

Тип размеров вида должен быть **True / Истинный**, что необходимо для физической
длины на изометрии. Макрос сам не переключает тип размеров, конфигурации и
документы, не разрешает lightweight-модели и не обновляет список вырезов.
Конфигурация исходной детали должна соответствовать выбранному экземпляру.

## Как выбираются тела и длины

- Очередь строится из `CutListFolder.GetBodies` исходной детали рамы.
  Несколько одинаковых тел в одной позиции получают отдельные результаты:
  для примера из журнала это **17 позиций и 27 тел**, а не 17 размеров.
  Имена тел могут повторяться: в этом журнале 27 тел имели 25 разных имён.
  Сопоставление использует native-идентичность тела, одинаковые имена не объединяются.
- Длина определяется по точному токену ссылки `LENGTH@@@`, а не по локализованному
  имени свойства. `TOTAL LENGTH` не используется. Требуется разрешённое связанное
  значение из кэша `Get6(..., True, ...)` и положительное десятичное число.
- Длины списка вырезов в этом варианте считаются миллиметрами; коэффициент 0.001
  проверяется совпадением с геометрической длиной каждого измеряемого ребра.
  Другая единица не угадывается.
- Рёбра берутся из видимых сущностей **только выбранного экземпляра рамы**.
  Каждое переводится в исходную деталь, проверяются тело и длина. Подходит только
  прямое ребро, длина которого равна требуемой длине тела из списка вырезов.
- Рёбра короче 20 мм не отбрасываются по прежнему условному порогу.
- Если в исходном теле рёбра нужной длины имеют разные направления, автоматический
  выбор неоднозначен: тело пропускается с причиной. Так размер ширины короткого
  профиля не выдаётся за размер его длины.
- Если тело скрыто, полное продольное ребро не видно, длина отличается после
  скоса/обработки, свойство не разрешено или геометрия неоднозначна, выводится
  конкретная причина. Размер короткой стороны и текстовый override не подставляются.

## Уже существующие размеры

Старые размеры сохраняются. Для зачёта существующего размера проверяются его
привязки к выбранному экземпляру, исходному телу и ребру нужной длины, а также
физическое значение и отсутствие числового override. Одного совпадения числа
недостаточно: одинаковые детали в разных экземплярах сборки не объединяются.

Успешный пробный размер 710 мм может быть зачтён как существующий, если API
подтвердит эти привязки. Неподдерживаемые или неоднозначные привязки явно отмечаются
в журнале; они не объявляются подтверждённым покрытием тела.
Если известно тело, но размер не удалось подтвердить, оно пропускается для
проверки. Если потенциально подходящий старый размер нельзя отнести к телу,
новое создание останавливается ещё до первой попытки, чтобы не добавить дубликаты.
Подтверждённые размеры чужих экземпляров и размеры с другой физической длиной
не создают такого ограничения. Проверяйте итог и сообщения о старых привязках.

## Расстановка и обработка отказов

- Надписи размещаются рядом с измеряемым телом; выход за контур тела и рамку вида
  допускается. Проверяются границы листа и оценочные области старых/новых размеров.
  Габариты текста и выносных линий не измеряются точно, заметки и вся геометрия
  вида как препятствия не анализируются.
- Для каждого размера отдельно измеряется двумерный отклик `SetPosition2`:
  базовая точка, пробы X и Y, затем обратная поправка. Это учитывает различные
  направления профилей, сохраняя исходный Z аннотации. Коэффициент пробного
  размера 710 мм не переносится на остальные тела.
- Вырожденная/плохо обусловленная матрица, слишком большая команда или конечная
  ошибка за пределами 0.01 мм не принимаются. Допуск не увеличивается.
- При отказе кандидата удаляется только размер текущей попытки. Затем может
  проверяться другое видимое ребро **той же требуемой длины** этого тела —
  не более восьми кандидатов на тело.
  Уже успешные размеры других тел сохраняются.
- Если после создания не получен handle или удаление не подтверждено, дальнейшее
  создание останавливается. Необработанный остаток очереди отмечается отдельно.
- Настройка ввода значения размера восстанавливается на выходе. Документ
  автоматически не сохраняется и не перестраивается.

## Статус проверки

Пользовательским запуском подтверждена одиночная проба Trial 1.3 на сборке:
истинная длина 710 мм, правильное тело и совпадение заданной и прочитанной позиции.
Массовый модуль прошёл статическую проверку и независимый review. Выражения
чистого решателя извлечены из исходника и численно проверены на единичном,
диагональном, повёрнутом, скошенном и отражённом откликах. Вырожденные и плохо
обусловленные матрицы, а также поправки более 50 мм отклоняются. Проверен
коэффициент успешной нативной пробы. Это не компиляция VBA и не COM-запуск.
Массовый запуск выполнен: 11 размеров созданы корректно, 8 труб пропущены из-за
отсутствия подходящих видимых рёбер. Покрытие труб пока не подтверждено.

Для первого массового запуска пришлите полный файл журнала из TEMP и снимок
изометрического вида. Сверьте количество результатов с числом тел списка вырезов;
наличие итоговой строки само по себе не означает, что все тела образмерены.
